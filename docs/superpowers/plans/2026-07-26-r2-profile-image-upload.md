# R2 Profile Image Upload Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add authenticated R2 presigned uploads for page profile images and replace the previous `users/profile/` object when a new image is finalized.

**Architecture:** The backend validates the page owner and upload metadata, signs a short-lived R2 S3 PUT URL, and exposes an authenticated completion endpoint. The browser uploads directly to R2, then completion verifies the object, deletes the old key, and writes the new key to `pages.image`; the frontend stores only the key and derives the public image URL from `VITE_R2_PUBLIC_URL`.

**Tech Stack:** Cloudflare Workers, R2 binding for HEAD/DELETE, AWS Signature Version 4 presigning, Hono, Drizzle, Valibot, TanStack React, Bun.

## Global Constraints

- R2 bucket name is exactly `test-images`.
- Object keys use the `users/profile/[filename]` prefix.
- Only image MIME types and files up to 5 MiB are accepted.
- `pages.image` stores an object key, never a presigned URL.
- Existing profile objects are deleted only after the replacement object is confirmed.
- Do not add new test files unless current repository conventions require it.
