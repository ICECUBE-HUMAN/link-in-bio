# demo 페이지 구현 계획

## Goal

`/demo`에 지정된 실제 userId의 최신 페이지 데이터를 제공하고, `$handle.tsx`의 편집 UI를
유지하면서 demo 경로의 모든 변경을 브라우저 메모리/object URL에만 반영한다.

## Scope

- `packages/api/src/index.ts`의 `demo` reserved handle 계약 확인/유지
- 실제 source page 조회기와 `$handle` loader 분기
- page/item/link/media/profile/settings 저장 경계의 local-only 분기
- frontend 테스트 파일은 AGENTS 정책에 따라 추가하지 않음

## Implementation units

### U1. Demo route data and reserved handle

**Files**

- Create: `apps/frontend/src/lib/demo/demo-page.functions.ts`
- Modify: `apps/frontend/src/routes/$handle.tsx`
- Verify: `packages/api/src/index.ts` reserved handle list

**Steps**

- [ ] source handle `tester`의 실제 page response를 읽고 지정된 userId를 검증한다.
- [ ] normalized handle `demo`에서 session query 없이 최신 source page response를 반환한다.
- [ ] loader data에 `isDemo`를 추가하고 demo를 edit mode로 연결한다.

### U2. Local persistence seams

**Files**

- Modify: `apps/frontend/src/lib/page/use-page-auto-save.ts`
- Modify: `apps/frontend/src/lib/page/use-link-metadata-enrichment.ts`
- Modify: `apps/frontend/src/components/page/page-image-editor.tsx`
- Modify: `apps/frontend/src/components/page/page-settings-menu.tsx`
- Modify: `apps/frontend/src/routes/$handle.tsx`
- Modify: `apps/frontend/src/lib/api/profile-image-api.ts` if local/blob image URL support is needed

**Steps**

- [ ] page autosave draft UI를 유지하되 demo mutation을 건너뛴다.
- [ ] grid editor `persistItems: false`, link enrichment no-op을 demo에 연결한다.
- [ ] media 선택과 profile image/crop을 object URL/local state로 처리한다.
- [ ] settings의 handle 변경을 local-only로 처리하고 logout/delete 외부 동작은 demo에서 숨긴다.

### U3. Verification and cleanup

**Steps**

- [ ] frontend test 파일은 만들지 않는다. 기존 관련 테스트/경계를 확인하고 수동 검증으로 대체한다.
- [ ] `bun run --filter @sinabro/frontend typecheck`를 실행한다.
- [ ] `bun run --filter @sinabro/frontend check`를 실행한다.
- [ ] `bun run --filter @sinabro/frontend build`를 실행한다.
- [ ] diff에서 demo 경로의 upload/mutation 누락과 일반 경로 회귀를 검토한다.

## Verification contract

- DEMO-01: loader는 session query 없이 지정된 source page GET 결과로 렌더된다.
- DEMO-02: page/item/media/profile/settings 변경은 네트워크 저장 요청 없이 화면에 반영된다.
- DEMO-03: `demo`는 reserved handle list와 기존 backend availability 계약으로 보호된다.
- DEMO-04: typecheck, check, build가 통과하고 일반 경로의 분기 외 변경이 없다.

## Definition of Done

- `/demo`가 지정된 실제 페이지의 최신 text, media, map, section, link 데이터를 보여준다.
- `$handle.tsx`의 toolbar, item controls, breakpoint, profile editing UI가 demo에서 활성화된다.
- demo에서 DB/R2/API 저장 호출이 발생하지 않는다.
- `demo`를 다른 사용자가 선점할 수 없다.
- frontend typecheck/check/build 결과와 수동 검증 범위를 최종 보고한다.
